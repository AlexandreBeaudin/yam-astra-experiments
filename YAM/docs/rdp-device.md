# RDP 设备服务接入

本接口为可选功能，默认关闭，与本机 8770 工作台共享同一 Workbench；安全守护进程仍是唯一电机控制权威。RDP Portal 调用端位于 rhosdata-platform 的 `/tel-workbench`。完整平台配置及协议见 RDP `docs/yam-device-workbench.md`（RHOS-PLAN-447）。

安装：在 gello_software 中保留原有 yam/realsense/mcap/guidance/dev extras，增加 `--extra platform`；例如 `uv sync --extra yam --extra realsense --extra mcap --extra guidance --extra dev --extra platform`。

配置 `~/.config/yam/rdp-device.json`，文件、私钥不得提交 Git：

```json
{
  "device_id": "yam-nuc-01",
  "station_id": "当前profile.name",
  "url": "https://yam-nuc-01.example.com:8771",
  "bind": "0.0.0.0",
  "portal_origins": ["https://rdp.example.com"],
  "public_key": "平台专用Ed25519公钥的base64",
  "tls_cert": "/home/rhos/.config/yam/tls/fullchain.pem",
  "tls_key": "/home/rhos/.config/yam/tls/key.pem"
}
```

平台签名私钥只放 RDP 后端，NUC 只拿公钥。Origin/URL 不带路径或末尾斜杠，station_id 必须等于当前 profile.name；TLS 证书必须在操作员浏览器受信任且匹配主机名。默认 bind=127.0.0.1，远程访问显式监听局域网并配置防火墙。不关闭浏览器安全限制；需要时在浏览器批准局域网访问。

在 `yam-operator` 用户服务 override 中设置 `Environment=YAM_DEVICE_CONFIG=/home/rhos/.config/yam/rdp-device.json`。确认双臂已安全停止后再重启服务，不能在采集中为启用新配置重启。没有配置时现有本机网页行为不变。

平台签名授权最长120秒，绑定本人任务、工位、策略、图片摘要、浏览器Origin及一次性challenge；NUC独占会话，录制中不能切换策略，使用revision拒绝旧操作。平台失联/授权到期后保留结束/保存/停止/下使能，禁止新录制。关闭页面不自动下使能，结束工作必须现场支撑确认。会话丢失时用本机8770停止、下使能，旧授权过期且状态offline/disarmed后才能由新平台授权重新连接；safe_hold不等于下使能。

每条MCAP `/guidance/initial`记录 source=rdp、人员、任务、工位、策略、图片及摘要、calibration_status=unverified_reference，不含授权凭据。工作台仅向平台回写进度元数据，不发送视频、机械臂state或MCAP。图片按参考图使用，不冒充 real2sim 已验证标定，叠加只在图像比例一致时开放。

本地测试（无硬件）：

```sh
cd gello_software

```

## 进度回写配置与恢复

设备JSON追加 `report_url`（可信平台HTTPS `/api/device/collection-events`）和 `report_token_file`（0600随机设备凭据文件，至少32字符）。RDP对应device追加 `report_token_sha256`，值为凭据SHA-256；不使用数采员密码。配置完成后只能在停止任务且从臂可靠支撑、下使能确认后重启服务。

私有SQLite队列 `~/.local/state/yam-operator/rdp-progress.sqlite3` 保存元数据收据及原签名。不要删除该文件、WAL或平台上下文来清除待同步提示。网络故障自动重试；任务转派/关闭或凭据错误会保留队列并提示，需管理员恢复合法任务/配置后补报。未完成文件不自动算成功，继续使用本机MCAP恢复流程核实；异常恢复尚需核对原条目与队列，不能绕过“未结束条目”直接完成平台任务。

MCAP的 `/guidance/initial` 新增 `episode_uuid`，包含任务/策略快照，不包含回写签名和凭据。只有文件已发布且持久化才回写saved。任务首次事件推进到采集中，成功/失败分别累计；只成功完成策略标记。废弃不计数。停止任务不完成平台任务，也不撤去电机支撑。

状态接口新增 `progress_sync`（pending/synced/blocked/unfinished/message）；网页“完成平台任务”调用 `/v1/complete-check`，要求采集进程停止、无待同步及未结束条目，再请求平台原完成接口。断网或任务状态变化后仍保留结束、保存、停止和下使能。

### 异常断电后的未完成记录清理

RDP工作台现在显示未完成MCAP数量，并提供“清理未完成记录”。只允许当前设备会话在任务已停止且电机offline/disarmed时确认操作；旧revision、运行中、保持中均拒绝。清理仅处理当前任务，将未保存残片移到`mcap/.discarded/`，原文件保留；成功/失败目录不受影响。对应孤立started事件补记discarded，未发布保存意图撤销，不虚增成功/失败计数。文件移动与队列事务中断后可重复执行，不会重复计数。清理后必须重新执行设备检查。

### 操作提示、逐条摆放与连续预览（2026-10-22）

操作提示优先显示正在执行的检查、上电、保存、停止等命令。初始化期间忽略旧采集器状态；慢速对齐完成后才按扳机阶段显示按下/松开提示。下使能后，未完成的平台任务在主操作区直接提供设备检查，检查通过才可重新上使能。

每个摆放策略对应一条成功记录。MCAP实际保存成功后，自动选择并授权下一条未完成策略；失败保存或废弃保持原策略。本机持久化成功记录先于平台同步也可触发切换；尚未发布的文件不会推进。已完成策略不能再次开始，全部成功后提示停止并下使能；切换授权失败时保留手动应用摆放入口，禁止继续录制旧的已完成策略。

三路预览由浏览器直连NUC的连续MJPEG流，在Canvas绘制并显示实际预览FPS，复用本机JPEG缓存、丢弃已被更新的帧，断流隐藏旧画面并重连。取代原150ms逐帧请求（约6FPS上限），源预览最多30FPS；实际帧率取决于相机、USB、CPU与浏览器。RDP不接收视频；NUC本机浏览器走本机服务，远程浏览器会接收NUC传来的预览流。预览不改变本地MCAP录制频率。

## 网页工位注册与本机配置向导（本地候选，2026-10-22）

平台组织管理员进入“系统管理 → 采集工位”（`/tel-devices`）。新增设备ID、工位ID、名称和可信HTTPS服务地址，新工位默认为停用。领取并下载一次性接入配置，在目标工控机浏览器打开 `http://127.0.0.1:8772/` 导入；完成本机配置后，回平台检查连接并启用。采集员没有工位管理权限。设备ID和工位ID登记后不可变；名称、地址、停用状态可修改，revision防止并发覆盖。禁用后最多120秒内旧授权仍可能有效，禁用不等于急停；迟到的已保存事件仍可补报。

管理员可直接修改工位列表，无需改代码或重启API。配置文件仍提供平台签名密钥、允许的Portal来源，以及首次导入的工位；数据库已存在记录不会被旧配置文件覆盖。平台仅保存回写凭据摘要，接入文件只在首次发放时返回，关闭前必须下载保存；原凭据无法再次下载，当前不提供凭据轮换。平台“检查连接”由管理员浏览器直连目标设备并验证设备/工位ID，仅表示当次可达，不等于持续在线心跳或机械臂检查通过。

本机向导扫描串口by-id、USB-CAN序列号和D405，允许逐个绑定左右主从臂及主/左腕/右腕三视角，并拍摄单帧确认视角。变更硬件映射需要上传对应的已标定YAML；不会替新硬件生成零点。保持原方向、640×480/30FPS。向导校验重复绑定、标定结构、证书与主机名、配置版本；仅停止、下使能且无待同步事件时允许应用。应用前先停设备服务，保存版本化文件及旧profile，切换systemd配置再启动；不会使能电机。应用后仍需平台连接与设备检查。CAN名称或序列号变化后检查/使能会被拒绝，须回向导重新确认，不会静默连接另一适配器。

部署人员首次安装硬件驱动、dialout权限、可信证书和YAM Python环境后，执行 `bash gello_software/scripts/install_station_setup.sh` 安装本机向导用户服务；新机没有operator服务时同时生成服务文件。服务通过sg dialout使用已授予的串口组权限，未加入dialout的账号仍须由部署人员配置权限。向导仅监听127.0.0.1:8772，限制Host/Origin与页面令牌，不向网络提供未认证配置入口；从其他电脑点“本机配置向导”会打开那台电脑的localhost，必须在目标工控机操作。原生部署的root权限、HTTPS证书申请和实际机械标定仍属首次安装前置工作。

平台新增迁移133（PR-ready前按主线定号），将工位登记与不含凭据的修改审计保存在PostgreSQL。无采集视频上传。新机注册测试使用虚拟设备，不把工位启用状态等同于电机使能。

### 默认本机识别与连接（2026-10-22）

工作台新会话默认“本机（自动识别）”。浏览器只探测固定的 `http://127.0.0.1:8773/v1/challenge`，将设备ID和工位ID同时与平台启用工位列表核对；匹配后显示本机工位名称，选择已发布且分配给本人的任务后自动建立签名设备会话。不会自动检查、上使能或开始采集。未注册、已停用、服务不可达或浏览器拒绝本地网络访问时明确提示，绝不自动连接列表里的其他机器。可手动重新识别或切换“远程工位（手动选择）”。不自动扫描局域网。

本机模式的状态、相机预览和控制全部经127.0.0.1:8773，不使用工位登记的远程URL；浏览器首次可能要求允许该平台访问本地网络。回环HTTP是浏览器可信本地地址的特殊情况，客户端仍拒绝普通局域网HTTP及其他HTTP端口，远程连接继续要求可信HTTPS。设备接口只监听loopback、严格校验Host/平台Origin、独占会话和签名授权；与8771共享同一个DeviceBridge，不能从另一个入口抢占控制。现有安装仍保留HTTPS远程入口及其证书配置，未改平台注册字段。

刷新后按会话保存的连接方式恢复。老版本的远程会话保留远程连接供安全收尾，不在录制期间自动切换传输；停止并断开后可以选择本机。主动断开不会立即自动重连，切换新任务或显式重试才重新连接。

同时修复sg权限包装进程下的systemd监督：operator服务使用Type=notify/NotifyAccess=all，由Python报告实际MAINPID，保留KillMode=process以免连带终止安全守护进程。安装脚本和本机服务已更新；纯回环入口仅做会话和元数据鉴权，不放宽机械臂控制门禁。

RDP 工作台只展示本人已领取的任务；请先到 TEL 任务页面领取。设备未启动且安全状态为 offline/disarmed 时，可以“取消选择”或直接改选任务，不必先检查。此操作只释放本机会话，不退回平台任务、不删除记录。设备服务同时检查独立采集进程，运行中不能释放控制会话。
