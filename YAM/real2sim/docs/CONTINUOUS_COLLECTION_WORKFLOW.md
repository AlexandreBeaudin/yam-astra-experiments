# 连续采集：自动下一条与失败重采

2026-09-23，本机 Xtrainer 三/四相机采集适配；共享桥接逻辑在 real2sim.collection。未向 YAM 部署，也未启动真机。

## 数采员流程

1. `conda activate Xtrainer`，按原方法启动节点和 `bash collect.sh`，选择任务。
2. 仅输入姓名全拼；指导模式的数据集名自动使用所选任务编号，例如 `dataset_zhangsan_TASK-X-0003_时间戳`。保留原现场标定和启动运动范围确认。
3. 按指引摆放，主臂原录制按钮开始，再按一次停止。相机图像、动作和指引侧车保存完成后，自动选择下一条。无需网页保持前台。
4. 手动遥操还原，按新的指引摆放，再按按钮录制。最后一条保持当前指引，不循环。
5. 如果刚录的一条失误，在开始下一条前点击网页“上一条标记失败并退回指引”。完整轨迹移动到 `本批次/collect_data/fail/原轨迹编号/`，包括所有相机、observation、指导 PNG、首帧叠加图及侧车。恢复失败轨迹开始时的布局、透明度和试采/正式模式，重新录制即可。

失败标记只作用于当前数采会话最近保存的一条，以 episode_id 核对，不接受网页传入磁盘路径。正在录制或保存时拒绝；过期请求拒绝，同一条重复操作不会再次移动或覆盖目录。失败轨迹保留原路径与 failed_at，质量标记为 failed，并从实时有效覆盖统计中排除。转换入口 scripts/4_collect2train_data.py 仅扫描数字命名的轨迹目录，跳过 fail。

未启用指引的普通采集仍需原任务名输入。试采按12条训练布局顺序切换，正式采集按130条清单顺序切换；失败后复用原模式的序列。录制中不能手动切换指引。异常退出及无帧录制不自动前进。

## 实现与版本

- 服务按会话、版本和试采/正式模式写入 workflow_<phase>.json；桥接工作线程保存最终轨迹侧车及索引后更新选择。按钮回调冻结开始时的指引，后续切换不改变已录轨迹。
- 网页通过 /api/fail 提交 episode_id；由拥有录制状态的桥接线程验证并移动，网页进程不直接操作轨迹目录。
- 新页面随新指导包发布，已发布旧包不修改；重新启动 collect 后加载新版。已有会话不会热替换。
- TASK-X-0003 包：runs/task_x_0003_continuous_workflow_20260923。
- TASK-X-0001 包：runs/task_x_0001_continuous_workflow_20260923。
- 两者仅更新流程与页面，位姿、标定、分组和投影 PNG 均保留。TASK-X-0003 继续使用透明仿真资产渲染。
