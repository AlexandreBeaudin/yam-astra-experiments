# 模型辅助任务道具建模

期望使用 gpt-6-astra 协助观察、提出几何假设、编写参数化建模脚本和迭代修正。
这里定义工作方式，不假定已接入该模型 API、已存在专用建模服务或模型能从 RGB 唯一恢复真实物理属性。
初期可人工在对话中执行同一配方；后续通过可替换的 ModelProvider 接入，不写死模型名称到核心。

## 输入证据包

- 同一时段的多视角关键帧与内外参；标明实际同步精度。
- 初始、接近、抓取、运输、放置、结束时刻，包含无遮挡帧。
- 分割/裁剪图、物体 ID、可见度、与机器人/桌面接触关系。
- 实测尺寸：杯高、口径、底径、壁厚；桌面高度。尺度来源、误差范围和单位必须记录。
- 颜色、材质、纹理近照；不见的背面/底部显式标为假设。
- 若有深度、CAD、扫描或商品尺寸可接入，但不能假定现有 JPG 中包含深度。

## 输出资产包

```text
assets/<asset_id>/<version>/
  recipe.json          参数、测量依据、假设、模型/提示版本、种子
  build.py             可复现的参数化建模脚本（后续实现）
  visual.glb           外观网格与材质
  collision/           凸分解或组合几何，独立于视觉网格
  physical.json        质量/惯量/摩擦/恢复系数，含来源与置信度
  frames.json          原点、抓取点、支撑面与对称性
  evidence/            来源帧引用与尺寸记录
  validation.json      留出视角/帧的误差和人工检查
```

首个样板用杯子：截面旋转生成内外杯壁与杯底，独立参数为高度、上下口径、壁厚、底厚。
视觉模型可以平滑细分，碰撞模型应保持杯腔可进入；一个覆盖整杯的凸包会把杯口封死，不能用于叠杯。
质量与摩擦优先实测/辨识，模型推测值只能标为 assumed，接触档前必须验证。

## 迭代闭环

证据 → 参数化配方 → 构建网格 → 三视角渲染 → 轮廓/关键点误差 → 修改可解释参数 → 留出验证。

先用几何误差优化尺寸和位姿，再调材质与光照。资产外形、相机位姿和光照不要全部无约束同时调整。
单个 3D 模型必须同时解释三个视角；禁止用每个视角各自的尺寸/位置规避几何矛盾。
记录人工编辑与推测项，避免生成结果覆盖真实测量。

## 动态道具

静态建模只解决“物体长什么样”，还需要解决“物体每一帧在哪里”。
第一版使用多视角 6D 跟踪 + 人工关键帧校正；遮挡时可用支撑面/抓取约束插值，但标记为估计。
对对称物体使用对称性误差，避免追逐不可观测的旋转。
视觉档可以使用整段估计轨迹；物理档只能用初态，后续参考轨迹只用于评估，不能注入仿真。
