# Stack cups 物料与初始摆放闭环

本轮使用已经估计重建的纸杯 v1，实际运行物料登记、布局生成、几何与 IK 检查、PhysX 静置、RTX top 渲染、50% 物体叠加和摆放核验。默认画面来自原演示首帧，不能把离线测试称为实时数采完成。

## 启动

在 `/mnt/sdb/rhos_collector/real2sim` 中：

```bash
# 已生成的结果可直接启动，无需重新运行仿真
.venv/bin/python scripts/serve_guidance.py
# 浏览器打开 http://127.0.0.1:8765

# 全流程重新生成到独立目录
.venv/bin/python scripts/run_distribution_pipeline.py --count 36 --seed 20260914 --run runs/distribution_new

# 检查代码中的关键几何/运动学约束
.venv/bin/python -m unittest discover -s tests -v
```

页面可以选布局、调整透明度、查看 top 仿真图、标注真实图上的三个杯口圆心、保存计划与实际偏差。标注顺序为左源杯、目标杯、右源杯。核验通过只表示当前假设下摆放误差不超过 15 mm，不表示插入精度达标。原图和叠加图分开保存，原始数据集不被修改。

## 各步骤的真实含义

1. `assets/registry/paper_cup.v1.json` 登记原点、单位、版本、重建来源和测试库存数量 3。资产 USD 有中空杯壁碰撞体，未认证物理参数。后续 RGBD 或图生三维资产可按相同字段入库。
2. `configs/tasks/stack_cups_distribution.json` 描述平台、三个角色、工作面、间距、投影边界、深度和间距分层。杯子绕竖轴对称，所以本轮不制造无意义的 yaw 多样性。
3. 确定性语义采样器覆盖两个源杯平均 X 坐标的 3 个深度区间 × 3 个展开间距区间。两侧源杯仅要求各自机械臂可达，目标杯独立采样于双臂公共操作区，这比让三杯整体平移更有效。种子和拒绝原因落盘；两源杯有反向深度偏移。当前没有调用外部 VLM API，也不假装模型已参与。
4. 相机使用现有 top 内参、外参和采集图像方向。通用投影模块支持畸变；本例 top 畸变为零。检查杯壁上下圆周的投影、12 px 边界和杯间图像重叠。
5. 独立 Xtrainer 适配器使用 6D IK、官方模型关节限位及已校准基座坐标。左右臂分别检查源杯抓取、上方接近、抬升、公共目标杯上方，共 8 个位姿，保存关节解和残差。圆杯本轮选择固定竖直抓取姿态；未搜索所有抓取姿态，拒绝不等于物体绝对不可达。
6. PhysX 把每组初始场景放入独立静置单元，模拟 1.5 秒，检查倾斜、末段漂移、支撑高度。这里只验证杯子在桌面上的静态稳定性；没有执行抓取或验证机器人碰撞。
7. RTX 使用现有机械臂初始姿态和改进夹具资产渲染 top 画面。通过有遮挡场景与仅杯子场景的语义分割面积对比，要求每个杯子至少 95% 可见。遮挡失败的布局不能保存采集核验。布局里会分别记录 IK、静置、可见性以及最终门槛结果。
8. 50% 叠加只覆盖渲染出的杯子像素，保留真实背景。真实画面里的原有杯子仍会存在，这是引导移动的参照，不应被图像编辑删除。可调整透明度看目标。
9. 实际位置核验当前是人工点击杯口中心，按直立杯、已知估计杯高反投影。它不是视觉自动识别或深度实测。保存原图哈希、标定哈希、资产版本哈希、计划/实际坐标、误差及模式；真实覆盖率必须从实际核验日志统计，不能拿目标布局数量代替。

## VLM / GPT 的接口

VLM 可以读取任务说明和已渲染图，提出语义布局；也可以由当前对话中的模型写候选文件。候选只能提供位置与理由，校验字段一律由程序重新计算。本轮简单的三圆杯任务先用分层采样更容易量化覆盖，后续复杂物料可增加语义提议器，保留同一检查器。

```json
[
  {
    "positions_m": [[-0.1,-0.38,0.063],[-0.12,-0.56,0.063],[-0.08,-0.74,0.063]],
    "rationale": "左右源杯展开，中间目标杯保持双臂操作空间"
  }
]
```

```bash
.venv/bin/python scripts/run_distribution_pipeline.py --proposals proposals.json --run runs/proposed_layouts
```

手动界面可以修改三维坐标、调用相同 IK/几何检查器、导出这个 JSON。候选在重新静置与渲染前不会得到 `guidance_ready`。外部候选的分布分层不自动计入默认采样器的九宫格计数。

## 实时接入

页面服务默认只监听本机。相机采集进程可把 top 原图用临时文件加原子重命名的方式发布为 JPEG；本服务读取它，不抢占摄像头设备。图像必须与既有标定相同的相机、分辨率、裁切和 180° 翻转约定。先从 `/api/state` 获取 `camera_config_sha256`，再启动：

```bash
.venv/bin/python scripts/serve_guidance.py --live-jpeg /absolute/path/top.jpg --camera-config-sha256 HASH
```

图像超过 2 秒未更新会报错；网页正常指导时自动更新，开始人工标注后冻结。冻结帧超过 60 秒不接受实时核验。哈希一致仅表示配置一致，并不能自动检测相机被移动；目前仍需操作者核对安装状态。后续应增加桌面标记板在线外参漂移检查。

`Camera`、投影、布局记录、前端、物料登记与仿真静置不依赖 Nova2 的运动学。更换平台时新增 `check(positions)` 的可达性适配器，提供机器人模型、关节限位、基座/工具坐标和任务抓取方式；当前命令行的默认装配仍为 Xtrainer，尚不是任意 URDF 自动即插即用。

当前右臂外参和夹具安装位姿尚待实测确认。IK 通过并不证明连通无碰撞路径、双臂无碰撞或抓取成功。新初始布局不能直接播放旧关节轨迹完成任务；应重新规划或通过策略闭环，并沿用已有真实接触实验来评估。完整三视角可见性、自动实际物体位姿检测、深度核验、实时采集员操作验证及按实际覆盖缺口主动补采是后续阶段。
