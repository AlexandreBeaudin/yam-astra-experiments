# 数采操作指南

适用于本机双臂、三相机。手里操作的是主臂，跟随运动的是从臂。

**每条数据：准备 → 松开、按到底、再松开两侧扳机 → 看到“录制中” → 做任务 → 结束 → 标注保存。**

## 1. 开始前

向负责人确认任务名、物品摆放和成功标准。检查三个相机无遮挡，机械臂运动范围无人无障碍，急停可用。

在机器人电脑终端执行：

```bash
cd /home/chenyuan/workspace/YAM/gello_software
scripts/teleop --recording-format mcap --check
```

看到“启动前检查通过”后启动。把 `pick_banana` 换成实际任务名，同一任务沿用同一个名称：

```bash
scripts/teleop --recording-format mcap --control-hz 200 --state-hz 200 --task-name pick_banana
```

保持这两个窗口可见：**终端看录制状态，相机网页看画面**。

## 2. 开始第一条

1. 看到“使能前确认”，确认周围可以运动，按一次 **Enter**。从臂开始慢速对齐。
2. 看到“未录制”，拿稳两个主臂，按屏幕提示操作：
   - 先把两侧扳机都松开。
   - 同时把两侧扳机按到底，稍停一下。
   - 再把两侧扳机都松开，等待对齐稳定。
3. 确认显示 **“录制中”**、计时开始，再执行任务动作。

按回车不会直接录制。准备和扳机确认期间从臂会慢速跟随，这段不写入数据。
只按单侧、只按一半、按住不松，都不会开始。开始录制后，扳机正常控制夹爪，松开不会结束本条。

## 3. 结束、保存和下一条

网页与终端任选一种操作，等状态更新后再进行下一步。

| 要做什么 | 网页按钮 | 终端按键 |
|---|---|---|
| 完成动作，结束本条 | 结束本条并标注 | 录制时 Enter |
| 达到任务成功标准，保存 | 成功保存 | 标注时 s |
| 已尝试任务但未成功，保留失败过程 | 失败保存 | 标注时 f |
| 误录或无效数据，不保留 | 废弃本条，再确认 | 标注时 d，直接废弃 |
| 物品摆好，准备下一条 | 准备下一条（机械臂将移动） | 就绪时 Enter |
| 停止任务 | 停止任务 | Esc 或 Ctrl+C |

保存后等到“就绪”，重新摆好物品，再准备下一条。**每一条都要重新完成“松开 → 按到底 → 松开”的扳机确认。**

**要保留本条，先结束并保存，再停止任务。直接停止会废弃当前未保存数据。**

## 4. 相机网页与频率显示

复制终端“相机实时预览”给出的**完整地址**打开，确认主、左、右三个视角都有画面。需要用按钮操作时，点击“取得操作权限”。同一时间只有一个网页能取得权限，终端仍可操作。

通过 SSH 连接时，在自己电脑另开一个终端，将 `ROBOT_HOST` 换成机器人地址：

```bash
ssh -N -L 8765:127.0.0.1:8765 chenyuan@ROBOT_HOST
```

保持转发窗口打开，再用自己电脑浏览器访问预览地址。每次启动使用终端给出的新地址，不要只打开 `http://127.0.0.1:8765/`。若终端提示了其他端口，转发时使用对应端口。

录制时，终端原地刷新频率统计，这些数字不是报错：

| 显示 | 含义 |
|---|---|
| ACTION | 动作频率，目标约 200 Hz |
| STATE | 左、右从臂反馈频率，可能高于 200 Hz，两侧可以不同 |
| CAM | 主、左、右相机帧率，各约 30 FPS |
| 调度跳期 | 本条累计错过的控制周期数，不是相机丢帧数 |

持续明显低于目标、数字长时间不更新或跳期快速增长时，结束本条并报告。网页偶尔卡顿不能单独证明录制数据丢帧，需结合终端和保存后的文件检查。

## 5. 收工

**保存最后一条 → 停止任务 → 在终端确认保存结果和机械臂状态。**

正常退出后，按终端提示选择：

| 输入 | 作用 |
|---|---|
| Enter | 保持当前位置，电机仍开启 |
| g 后 Enter | 重力补偿，按现场培训操作 |
| o 后 Enter，再输入 o 后 Enter | 关闭电机，先用可靠支架支撑所有从臂 |

关闭网页不会停止任务，退出任务不会自动关闭电机。出现危险用**硬件急停**；出现 `FAULT` 时，不能认为从臂仍被托住，应停止操作并联系技术人员。

收工交接任务名、成功／失败条数和异常情况。数据由程序保存或废弃，不直接移动、删除文件。

## 6. 遇到问题

| 提示或现象 | 怎么处理 |
|---|---|
| 一直显示“未录制” | 按当前提示完成两侧松开、按到底、再松开；拿稳主臂等待对齐。仍无变化时报告 |
| USB 2.x 黄色提示 | 最终检查通过即可继续 |
| `PERMISSION` / `permission denied` | 使用下方权限命令；仍失败时报告 |
| 相机出流失败、`VIDIOC_S_FMT`、`Input/output error` | 关闭其他占用相机的程序，重新检查；仍失败时报告 |
| 网页无画面或断线 | 查看终端，检查 SSH 转发并刷新网页；持续异常时在终端结束本条后排查 |
| 主臂反馈过期、`FAULT`、左右映射或动作异常 | 停止操作，查看终端安全状态并报告 |
| 守护进程超时、协议过旧 | 联系技术人员处理，不自行强杀守护进程 |
| 保存失败、空间不足 | 保留当前窗口和报错，联系技术人员处理后再录下一条 |
| 提示有未完成数据 | 按提示 f 恢复为失败，d 废弃；不确定时先询问负责人 |

权限命令（账号须已加入 `dialout` 组，在第 1 节目录执行）：

```bash
sg dialout -c 'scripts/teleop --recording-format mcap --check'
```

检查通过后再启动，替换任务名：

```bash
sg dialout -c 'scripts/teleop --recording-format mcap --control-hz 200 --state-hz 200 --task-name pick_banana'
```

报告问题时提供：**发生时间、任务名、完整报错、日志路径、机械臂当前状态**。机械臂使能时不要拔插共用 USB Hub 或其电源。

## 7. 数据位置

本指南命令保存到：

```text
/home/chenyuan/workspace/YAM/data/任务名/mcap/
├── success/       成功数据
├── fail/          失败数据
└── .in_progress/  未完成数据
```

负责人可按 [多频率录制说明](gello_software/docs/multirate_mcap.md) 检查频率、视频和数据完整性。共享数据盘不是备份。

## 诊断提示

录制文件和编码器在准备阶段初始化，准备及扳机动作不保存。遇到“安全保持未确认”时，以故障状态处理，未完成数据留待恢复。

“数据已保存；临时文件待清理”表示已保存成功，不需要重复标注。启动时会尝试清理残留；若持续提示，将报错交给技术人员。

程序升级后，旧守护进程可能因代码／配置不匹配而拒绝复用。先支撑从臂，按正常停机流程退出旧进程，再启动。终端会输出关节诊断日志路径；对齐失败时保留该日志。技术细节见 [诊断说明](gello_software/docs/teleop_diagnostics.md)。
